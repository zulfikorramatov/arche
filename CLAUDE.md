# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`arche` is a Go (1.25) HTTP service template built around a clean layered architecture,
an OpenAPI design-first HTTP layer, and reusable infrastructure packages (Postgres, Redis,
Kafka, logging). It ships both an HTTP server (`cmd/app`) and a Cobra CLI (`cmd/cli`).

## Commands

All common tasks go through the `Makefile` (`make help` lists them):

- `make run` — run the HTTP server locally (loads `.env` from the project root via `godotenv`).
- `make build` / `make build-cli` — build `bin/arche` (server) / `bin/arche-cli` (CLI).
- `make test` — `go test -race -count=1 ./...`. Run one test: `go test -race -run TestName ./internal/service/...`.
- `make lint` — `golangci-lint run` (config in `.golangci.yml`; v2 format).
- `make fmt` — `gofmt -s -w .` + `go vet ./...`.
- `make generate` — **regenerate HTTP code from the OpenAPI spec** (see below). Run this after any `.yaml` spec change.
- `make up` / `make down` — docker-compose stack (Postgres, Redis, one-shot migrate).
- `make migrate-up` / `make migrate-down` / `make migrate-new name=add_xxx` — golang-migrate (requires the `migrate` CLI and a running Postgres; `POSTGRES_DSN` overridable).

## Architecture

### Layered flow

Request wiring lives in `internal/app/app.go` (`Run`), which is the composition root:
config → infra (`pkg/postgres`, `pkg/redis`) → repository → service → handler → router → `http.Server`
with graceful shutdown on SIGINT/SIGTERM.

The layers, and their dependency direction (each depends only inward via interfaces):

- `internal/repository` — SQL against `*postgres.Pool` (pgx). Returns `internal/entity` types.
- `internal/service` — business logic (e.g. bcrypt auth). Depends on a repo **interface** defined in the service package.
- `internal/http/handler` — implements the generated `api.StrictServerInterface`; translates `entity` ↔ generated `api` models. Depends on a service **interface** defined in the handler package.
- `internal/http` (`router.go`) — builds the chi router, wires middleware, wraps with Elastic APM.

Note the interface-at-consumer convention: `userService`/`userRepository`/`userAuthenticator`
interfaces are declared in the package that *uses* them, not where they're implemented.

### OpenAPI design-first HTTP layer (important)

The HTTP contract is the source of truth. **Never hand-edit `generated/api/*.go`** — they are
regenerated by `make generate` and overwritten. To change the API, edit the spec and regenerate:

- `generated/api/definitions.yaml` → data **schemas** (`User`, `Error`, request bodies) → `definitions.go`.
- `generated/api/api.yaml` → **operations** (paths, params, requestBody, responses, security) → `gen.go` (routing + `StrictServerInterface` + embedded spec).

Request validation (types, `required`, formats, and Basic-Auth) is enforced **automatically** in
`internal/http/middleware/validator.go` from the embedded spec, before handlers run — do not
duplicate it in handler code; express constraints in the YAML instead. Basic-Auth's
`AuthenticationFunc` calls `UserService.Authenticate`.

See `OAPI_GUIDE.md` for a full worked example of adding an endpoint (guide is in Russian).
Codegen options live in `generated/api/cfg.yaml` and `definitions-cfg.yaml` (strict-server, chi,
embedded-spec, nullable-type). Uses `go tool oapi-codegen` (declared as a Go tool dependency).

### `pkg/` — self-contained infrastructure

These packages know nothing about `internal/*` or env vars; callers fill a `Config` struct and pass it in.
`internal/config` mirrors each `pkg` `Config` one-to-one so `app.go` can do direct conversions like
`postgres.Config(cfg.Postgres)` — if fields drift, the build breaks (intentional guard against desync).

- `pkg/postgres` — pgxpool wrapper with Elastic APM instrumentation (`apmpgxv5`). `Pool` is a type alias for `*pgxpool.Pool`.
- `pkg/kafka` — franz-go wrapper. Producer = guaranteed delivery (`acks=all`, idempotent, sync). Consumer = at-least-once (auto-commit off, per-message commit after processing). **Handlers must be idempotent.** See `pkg/kafka/README.md`.
- `pkg/redis` — go-redis with optional Sentinel and key-prefix support.
- `pkg/logger` — slog wrapper with Elastic APM correlation (`apmslog`).
- `pkg/money` — currency-aware money type (bojanz/currency).

### Config

`internal/config/config.go` loads via `cleanenv` + `godotenv` (struct tags `env` / `env-default` /
`env-separator`). See `.env.example` for all variables. Config is loaded once in each entrypoint's
`main`/`PersistentPreRunE` and passed down explicitly.

### CLI

`cmd/cli` is a Cobra app. `cmd/cli/deps` holds shared dependencies (Postgres pool) opened in the root
command's `PersistentPreRunE` and closed in `PersistentPostRun`. Subcommands live under `cmd/cli/<domain>/`.

## Conventions

- Errors are wrapped with `fmt.Errorf("...: %w", err)` at each layer boundary.
- Adding an endpoint: edit spec YAML → `make generate` → implement the handler method → add service/repo methods. Follow `OAPI_GUIDE.md`.
- `generated/api` is excluded from linting; `pkg/redis/redis.go` (errname) and `pkg/kafka/consumer.go` (nilerr) have targeted lint exclusions.
